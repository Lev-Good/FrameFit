### באגים שהתגלו בהתקנה בשטח ותוקנו (2026-09-14)

- [x] **אזור העבודה נגמר לפני האזור הגלוי — רצועה מתה בגובה סרגל המשימות.** דווח מהתקנה
      אמיתית (שוליים L196 R213 T37 B410 על מסך 1920×1080): אזור העבודה הסתיים ב-`1511×585`
      במקום `1511×633`, ומקסם השאיר רצועה מתה בתחתית האזור הגלוי. במקביל סרגל המשימות
      נשאר בתחתית המסך, בתוך השוליים שהוגדרו כמוסתרים, ולא נעלם.
      **תוקן:** קיזוז הקצאות קיימות (FR-5.1, `WorkAreaCalculator`) והסתרת סרגל המשימות
      (FR-5.2, `TaskbarHost`). **אומת בפועל:** אזור העבודה הגיע ל-`196,37 1511×633` =
      האזור הגלוי **במדויק**, בשני מצבי שוליים, והסרגל הוחזר בשחזור.
- [x] **הבדיקה העצמית לא הייתה חושפת את התקלה** — היא הסתפקה בבדיקת **הכלה** של אזור
      העבודה בתוך האזור הגלוי, ולא בדיוקיות. נוספו בדיקה שמשווה למידה מצופה, בדיקה לסרגל
      המשימות, ומקרה של שוליים עמוקים (תרחיש המסגרת).
- [x] **סרגל המשימות הוסתר — התנהגות שלא התאימה למשתמש.** דווח מהתקנת `v0.1.1`:
      הסרגל נעלם לגמרי ולא נשאר שמיש. **טופל (D13, ואחר כך תוקן ב-D14):** ברירת המחדל
      שונתה תחילה לעיגון הסרגל באזור הגלוי, ומשהתברר שנמדד שאי אפשר להזיז אותו — לאי-התערבות.
- [x] **הסרגל "עוגן" אך בפועל נשאר במקומו — הבדיקה השוותה לתוכנית ולא למציאות.** דווח
      מהפעלה חיה (D14): הלוג והבדיקה דיווחו הצלחה בעוד הסרגל ישב בקצה המסך, ואזור העבודה
      הקצה לו רצועה ריקה של 48 פיקסלים בתוך האזור הגלוי (רצועה מתה חדשה).
      **תוקן:** `TaskbarHost.MoveInto` מאמת את המלבן שנקרא חזרה מהמערכת ולא את הצלחת
      `SetWindowPos`; אם המערכת החזירה את הסרגל — הפעולה מדווחת ככישלון, הסרגל מוחזר
      למקומו, ולא נגזעת רצועה. הבדיקה העצמית מודדת מעתה את הסרגל **בפועל** ומקבלת את שני
      המצבים העקביים (מעוגן ומרוצף מול התוכן, או דבוק בקצה עם אזור עבודה מלא).
      **אומת:** בגרסת `0.1.3` המותקנת — 16/16, אזור העבודה = האזור הגלוי במדויק
      (`196,37 1511×633`), והסרגל מזוהה כמי שהוחזר ל-`0,1032 1920×48`.
- [x] **הוחלט (2026-09-14): אין סרגל חלופי, והסרגל נשאר במקומו.** המשתמש בחר שלא
      להוסיף סרגל של FrameFit לאזור הגלוי, ולא להתערב בסרגל של Windows (ראו
      `DECISIONS.md#d14`). בהתאם לכך: ברירת המחדל היא `LeaveInPlace`, אפשרות "ניסיון לעגן"
      **הוסרה מהממשק** (הקוד נשאר כניסוי בלבד, ונבדק בבדיקה העצמית), ופרופיל שמור עם המצב
      הזה נטען אוטומטית כ"יישאר במקומו". הפרופיל השמור של המשתמש עודכן ל-`TaskbarMode = 2`
      והשדה הישן `HideTaskbar` הוסר (`settings.json.bak` נשמר כגיבוי).
- [x] **בנייה והתקנה של `0.1.4`.** המתקין נבנה (0 אזהרות, 0 שגיאות) והותקן מעל `0.1.3`
      (קוד יציאה 0; ARP ו-`FileVersion` = `0.1.4.0`). **בדיקה עצמית של הקובץ המותקן: 16/16**
      — ובהן השוליים האמיתיים שהגיעו לאזור עבודה `196,37 1511×633` (האזור הגלוי במדויק).
- [x] **הסרגל שעוגן גזל מהתוכן בלי לעדכן את אזור העבודה.** אחרי המעבר לעיגון, אומת שהסרגל
      עוגן ב-`196,622 1511×48` אך אזור העבודה נשאר `196,37 1511×633` — כלומר חלון ממוקם
      היה נסתר מתחת לסרגל. **תוקן (FR-5.3):** `WorkAreaPlan.BottomAnchor` גורע את גובה
      הסרגל מאזור העבודה; **אומת בפועל:** התוכן `196,37 1511×585` והסרגל `196,622 1511×48`
      ממלאים יחד את האזור הגלוי `196,37 1511×633` — בלי חור ובלי חפיפה. הבדיקה העצמית
      בודקת כעת גם שהסרגל **נשאר גלוי** בזמן העיגון, ולא רק שהוא הוחזר בשחזור.
- [ ] **מגבלה שנמדדה ולא נפתרה — במסלול ההסתרה בלבד:** כשהשוליים בכל צד **קטנים** מגובה
      סרגל המשימות, Windows אינו מוותר על ההקצאה שלו גם כשהסרגל מוסתר, ואותם פיקסלים גלויים
      אינם ניתנים להחזרה. הקוד מקזז מה שאפשר ומדווח על ההפרש כאזהרה (לוג, הודעת החלה, אבחון).
      במסלול ברירת המחדל (עיגון) המגבלה אינה רלוונטית: הרצועה שמתחת לתוכן היא הסרגל עצמו.

### באגים שהתגלו בספיקים ותוקנו

- **גודל מבנה שגוי:** `Marshal.SizeOf<MONITORINFOEX>()` החזיר 72 במקום 104, בגלל חסר
  `CharSet.Unicode` על המבנה — ולכן `GetMonitorInfoW` נכשל בשגיאה 87 ומיפוי המסכים
  החזיר **אפס מסכים** בשקט, בלי חריגה. תוקן, ונוספה בדיקה קבועה לגודלי כל מבני האינטראפ.
- **נתיב ה-EDID ברישום:** `EnumDisplayDevices` מחזיר מזהה מופע סינתטי
  (`...\{guid}\0000`) שאינו קיים ברישום. הרשומה האמיתית נמצאת תחת מזהה חומרי שונה.
  תוקן באיתור לפי מזהה החומרה.

      לראות "עדיין מועבר" ולהחזיר אותו אל הרצועה המעוגנת. **תוקן:** המצב מנוקה תחת המנעול
      *לפני* הפעולות, פעולת ההחזרה שנכשלה מדווחת כאזהרה, ואימות־השחזור קורא את מלבן הסרגל
      ממערכת ההפעלה (`ReadCurrentRect`) ולא מהמצב השמור. **אומת:** 16/16 בשתי הרצות רצופות
      מהמקור, ואחר כך 16/16 על הקובץ המותקן — בשני המקרים הסרגל חזר ל-`0,1032 1920×48`.
      מכיוון שהבנייה הקודמת כבר הותקנה, בוצע מסלול נקי: הסרה (`msiexec /x`, קוד 0) ואחריה
      התקנה של ה-MSI המתוקן; בהסרה — הקבצים והקיצור דרך הוסרו, קובץ ההגדרות נשמר.
- [x] **אימות התקנה של הבנייה המתוקנת מעל 0.1.0 (MajorUpgrade).** בוצע בפועל: המתקין
      `FrameFit-v0.1.1-x64.msi` נבנה, הותקן מעל 0.1.0 (קוד יציאה 0), והקובץ המותקן עודכן
      ל-`FileVersion=0.1.1.0`, `Company=Lev-Good`. ה-MajorUpgrade הסיר את המוצר הקודם
      (`FindRelatedProducts` → `RemoveExistingProducts`), רשומת "הוספה או הסרה של תוכניות"
      מציגה `FrameFit 0.1.1.0`, קיצור הדרך מצביע על הקובץ החדש, והגדרות המשתמש נשמרו.
      **בדיקה עצמית של הקובץ המותקן: 16/16 עברו** — ובהן המקרה עם השוליים האמיתיים
      (L196 R213 T37 B410), שהגיע לאזור גלוי `1511×633` **במדויק** (לפני התיקון: `585`).
      אחרי הבדיקה: אזור העבודה חזר ל-`1920×1032`, הסרגל גלוי, ואין קובץ סימון יתום.
- [ ] **מקום רשומת ההסרה (ARP) אינו תואם את הצהרת ה-Scope.** בהתקנה שאומתה — בהקשר
      שאינו מוגבר — הרשומה נוצרה תחת `HKLM\…\Uninstall`, בעוד החבילה מוצהרת `Scope="perUser"`
      והקבצים הותקנו ב-`%LOCALAPPDATA%`. גם בלוג של `0.1.2` נרשם
      `Determined that existing product ... is installed per-user`, אך הפעולה בוצעה בהקשר
      ה-service. **טרם הובהר** אם זו התנהגות תקינה של Windows לחבילה "דו-שימושית", או הצהרה
      חסרה בחבילה; יש לבדוק התקנה בלחיצה כפולה ולהחליט אם לשנות את ה-`Scope` או להשאיר כמו
      שהוא (הרשומה נראית למשתמש וההסרה מהממשק עובדת).
- [x] **הרצת התוכנה המותקנת מול הפרופיל האמיתי (החלה חיה).** בוצעה בהתקנת `0.1.2` עם
      השוליים האמיתיים (L196 R213 T37 B175): ההחלה עבדה — שוליים שחורים, עכבר חסום, אזור
      עבודה `196,37 1511×820` — והמסך שוחזר במלואו במקש המילוט (`Ctrl+Alt+Shift+F12`) ולאחריו
      סגירת התהליך. בהרצה החיה נמדדה גם התקלה שתוקנה ב-`0.1.3` (רצועה מתה של 48 פיקסלים).
